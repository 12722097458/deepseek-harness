# Agent Note: 兼容 Windows stat 接口的 Lefthook 锁身份比较

Status: implemented

[English](2026-09-03-windows-lefthook-lock-identity.md) | 中文

## 问题

Node 在 Windows 上通过 `fstat` 和 `lstat` 读取同一个锁文件时会返回不同的 `dev` 值，但文件索引保持稳定。

工作树级 Lefthook 安装器在创建和释放锁时同时比较这两个字段，因此 Windows 上的每次安装都会误报所有权已变化，并留下锁文件，导致下一次安装把它判定为 stale。

## 决策

`scripts/install-lefthook.mjs` 在 Windows 上比较文件索引，在其他平台上同时比较设备号和文件索引。

统一的身份检查覆盖锁发布、锁释放和并发初始化检查；锁内容精确匹配、普通文件检查、符号链接拒绝和所有者进程检查保持不变。

安装器测试套件增加 Windows 专项回归：运行真实临时工作树安装，并验证安装成功且锁文件已清理。

## 备选方案

**在 Windows 上忽略文件身份。** 不采用，因为同一路径被替换的锁仍必须在删除前被检测出来。

**通过额外路径查询规范化 `fstat`。** 不采用，因为额外查询会扩大锁创建与身份验证之间的竞态窗口。

**改用时间戳或文件大小比较。** 不采用，因为其他进程替换锁后这些字段仍可能相同；Windows 的文件索引是两个接口都能稳定提供的身份信息。

## 影响

Windows 安装不再因为正常的 `fstat`/`lstat` 元数据差异而失败，成功安装会释放仓库锁，后续工作树可以继续安装。

Windows 上的替换检测仍依赖文件索引，其他平台仍依赖设备号和文件索引；所有者进程已退出的锁仍需要手动恢复。

## 验证

身份检查修复后，Windows Lefthook 临时工作树套件覆盖并发安装、锁释放、stale 锁和所有权变化场景并通过。
